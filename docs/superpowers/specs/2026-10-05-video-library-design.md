- 상태: **초안 — 사용자 검토 대기**

- 과제: 바이브코딩대학 3회차 「나만의 자동화 플러그인 구축 및 웹 시각화」
- 참고: [kuntae802/lecture-pipeline](https://github.com/kuntae802/lecture-pipeline) (구조·설계 아이디어만 참고, 코드는 새로 작성)

## 1. 목적과 성공 기준

**한 줄 요약:** 유튜브 영상 링크 하나를 넣으면, 자막을 교정·교열하고 목차·요약·용어집·번역·FAQ로 정리해 **내 PC의 영상자료실**에 쌓고, 원하면 **Railway 웹**에도 올려 보여 주는 Claude Code·Codex 겸용 플러그인.

지금까지 Lilys AI로 하던 "유튜브 영상 → 강의 자료" 작업을 내 도구로 대신한다. 개발 영상뿐 아니라 금융·경제·투자, 과학기술, 의학·보건 등 여러 분야 영상을 넣는다.

### 과제 체크리스트와 성공 기준

| 과제 체크리스트 | 성공 기준 |
|---|---|
| ① 내 플러그인 마켓플레이스에 등록 | 공개 GitHub 저장소를 마켓플레이스로 등록하고, Claude Code와 Codex 각각에서 새로 설치한 뒤 처음부터 끝까지 실행된다 |
| ② 1:1 수업에서 조교에게 사용 안내 | 조교가 설치 안내서만 보고 **토큰 없이** 자기 PC에서 영상을 처리하고 결과 화면을 본다 |
| ③ 사용 과정 혹은 결과를 웹으로 시각화·배포 | 결과 JSON을 Railway 서버로 전송하고, 공개 주소에서 데모 강의(바이브코딩대학 영상)의 목록·강의 화면이 동작한다 |

### 사용자별 쓰임

| 사람 | 쓰는 방식 | 결과가 남는 곳 |
|---|---|---|
| 본인 | PC + Railway 업로드(토큰 설정) | 내 PC + 내 Railway |
| 조교 | PC만 | 조교 PC |
| 과제 확인자 | Railway 공개 주소 | — (보기만) |
| 수강생·지인 | PC만 | 각자 PC. 내 서버에는 아무것도 남지 않는다 |

## 2. 범위

**포함**
- 유튜브 링크 1개 처리(사람이 만든 자막 우선, 없으면 자동자막)
- 2단계 오전사 교정(전체 맥락 파악 → 맥락 기반 교정) + 교열(띄어쓰기·맞춤법·문장부호)
- 분야 판정, 2단 목차·챕터 요약, 영상에서 언급된 자료, 용어집(비전문가 풀이 + 비유), FAQ
- 번역: 외국어 영상 → 한국어(자동), 한국어 영상 → 영어(요청할 때만, 전사만)
- 내 PC 영상자료실 + PC 전용 미니 서버 + 목록·강의 화면
- Railway 서버(업로드, 저장, 관리자 로그인, 공개/비공개), 공개 배포
- 대화창 질문(플러그인이 설치된 Claude Code·Codex 등에서)
- 마켓플레이스 공개와 설치 안내서

**제외 (이번 범위 아님)**
- 영상 파일 받기·편집본 만들기 — 4회차(AWS) 과제로 예상. `lecture.mode` 필드로 자리만 남긴다
- 자막 없는 영상(음성 인식) — 자막이 없으면 안내 후 멈춘다
- 재생목록·라이브 방송·비공개·연령 제한·회원 전용 영상, 유튜브 계정 로그인(쿠키)
- 유튜브 외 입력(PDF·웹페이지), 블로그 글 변환
- 손님 토큰, 메모·즐겨찾기, 용어집 모아보기
- 뷰어 화면 안에서 AI를 직접 부르는 채팅

## 3. 전체 구조

```
[내 PC]
  video-library 플러그인 (Claude Code · Codex)
     │  처리 결과 저장 (항상)
     ▼
  문서/영상자료실 ── PC 전용 미니 서버(127.0.0.1) ──▶ 브라우저: 목록·강의 화면
     │
     │  업로드·진행 보고 (토큰이 설정된 경우에만)
     ▼
[Railway]  뷰어 서버 + 볼륨(/data, 파일 저장) ──▶ 공개 주소: 같은 목록·강의 화면
```

- **일 나누기:** 기계적으로 정해지는 일(받기·정리·검사·조립·저장·서버)은 파이썬 스크립트가, 판단이 필요한 일(교정·교열·분야·목차·용어집·번역·FAQ·질문 답변)은 AI가 `SKILL.md`의 지시문(브리프)을 보고 한다. **AI 결과는 스크립트 검사를 통과해야만** 다음 단계로 간다.
- **화면은 한 벌:** 목록·강의 화면(HTML·CSS·JS, 빌드 과정 없음)을 PC 미니 서버와 Railway 서버가 같이 쓴다.
- **서버 코드도 한 벌:** 같은 파이썬 서버 프로그램이 저장소만 바꿔 끼운다 — PC는 파일 저장소(읽기 전용), Railway는 같은 파일 저장소 형식을 볼륨(`/data`)에 쓰는 저장소 + 로그인·업로드(10-06 사용자 결정: PostgreSQL 대신 파일 저장).
- **PC가 원본, Railway는 사본.** 서버 데이터가 사라져도 PC에서 다시 올리면 복구된다.

### 코드 단위 (`scripts/video_library/`)

| 모듈 | 하는 일 | 의존 |
|---|---|---|
| `config` | 영상자료실 위치, `config.json`(서버 주소·토큰) 읽기 | 표준 라이브러리 |
| `doctor` | 환경 점검, OS별 설치 명령 안내 | — |
| `fetch` | yt-dlp 파이썬 라이브러리로 정보·자막 받기 | `yt_dlp` |
| `preprocess` | 자막 → 문장 목록(번호·시작·끝·텍스트) | — |
| `chunk` | 약 10분 단위 조각 + 앞뒤 읽기 전용 맥락 | — |
| `validate` | AI 결과 검사기 모음(교정·교열·목차·번역·FAQ·용어집) | — |
| `merge` | 조각별 결과 검사 후 합치기 | `validate` |
| `assemble` | `lecture.json`·`transcript` 파일 조립, 스키마 검사 | `validate` |
| `library` | 영상자료실 갱신(`index.json`, 원자적 교체, `app/` 복사) | — |
| `jobs` | 진행 상황 기록(로컬 파일 + Railway 보고) | — |
| `search` | 전체 강의 검색(메모리 색인) | — |
| `server` | 웹 서버 핵심(라우팅·정적 파일·API), 저장소 인터페이스 | `search` |
| `store_file` | PC용 파일 저장소(읽기 전용) | — |
| `store_hosted` | Railway용 파일 저장소: `store_file` + 업로드·공개 상태·삭제·진행 보고 저장 | `store_file`, `validate` |
| `auth` | Railway 관리자 비밀번호 해시(PBKDF2)·업로드 토큰 해시 비교, 로그인 세션, 로그인 시도 제한 | 표준 라이브러리 |
| `remote` | `config.json`(서버 주소·토큰) 읽기·쓰기, Railway 요청 | 표준 라이브러리 |
| `upload` | Railway로 `lecture.json` 업로드 | `remote` |
| `connect` | 사용자 터미널에서 Railway 연결: 관리자 비밀번호(숨김 입력)·업로드 토큰 생성 → 해시를 Railway 변수로 설정 | `remote`, `auth`, Railway CLI |

통합 검색은 PC와 Railway 모두 같은 `search` 메모리 색인을 쓴다. Railway도 `index.json`이 바뀔 때(업로드·삭제) 파일에서 다시 읽어 색인을 만든다(강의 수백 개 규모를 가정, 넘어서면 DB 검색으로 바꾼다).

플러그인 쪽은 `yt_dlp` 외에 서드파티 패키지를 쓰지 않는다. Railway 서버는 표준 라이브러리만 쓴다(추가 패키지 없음).

## 4. 내 PC 데이터 — 영상자료실

위치 기본값: 사용자 **문서 폴더/영상자료실**. Windows는 문서 폴더의 실제 위치(OneDrive로 옮겨진 경우 포함)를 시스템에 물어서 찾고, Mac은 `~/Documents/영상자료실`. 환경변수 `VL_HOME`으로 바꿀 수 있다. 처음 실행할 때 없으면 만든다.

```
영상자료실/
├─ 영상자료실 열기.bat / 영상자료실 열기.command   더블클릭 → 미니 서버 켜고 목록 열기
├─ app/                     화면 파일 + 서버 실행 파일 사본 (실행할 때마다 플러그인 최신판으로 갱신)
├─ config.json              Railway 주소·업로드 토큰 (선택, 공개 금지)
├─ index.json               목록 데이터 (강의별 요약 정보)
├─ jobs/<job_id>.json       진행 상황
├─ .server.json             실행 중인 미니 서버의 포트·프로세스 번호
└─ lectures/<영상ID>/
   ├─ raw/                  받은 정보(info.json)·자막(json3)
   ├─ build/                중간 산출물 (문장 목록, 조각, 맥락표, AI 결과)
   ├─ lecture.json          최종 결과
   ├─ transcript.<언어>.txt         전체 스크립트(텍스트만)
   └─ transcript.<언어>.timed.txt   전체 스크립트(시간 포함)
```

- `app/`에 서버 실행 파일 사본을 두는 이유: 플러그인 설치 폴더는 업데이트마다 경로가 바뀌므로, 열기 파일이 항상 같은 경로를 가리키게 하려고.
- **영상 하나에 항목 하나:** 폴더 이름이 영상ID다. 재처리는 `lectures/<영상ID>.tmp/`에서 하고 **성공해야만** 기존 폴더와 바꾼다.

## 5. 약속 (데이터 형식과 전송 규칙)

### 5.1 `lecture.json` (schema_version `1.0`)

```jsonc
{
  "schema_version": "1.0",
  "lecture": {
    "id": "<영상ID>",                 // 영상 하나에 항목 하나
    "video_id": "<영상ID>",
    "source_url": "https://www.youtube.com/watch?v=<영상ID>",
    "title": "...", "channel": "...",
    "duration": 1942.0,              // 초
    "thumbnail_url": "https://i.ytimg.com/...",
    "language": "ko",                // 원문 언어 (ISO 639-1)
    "field": "dev",                  // dev | finance | science | medical | other
    "one_liner": "한 줄 소개",
    "mode": "text",                  // 이후 영상 모드 확장용
    "processed_at": "2026-10-05T14:03:00+09:00",
    "pipeline": {
      "version": "0.1.0",
      "caption_kind": "manual",      // manual | auto
      "skipped": ["faq"]             // 실패로 빠진 선택 단계
    }
  },
  "segments": [                      // 원문 언어, 교정·교열 반영
    {"idx": 1, "start": 3.0, "end": 7.2, "text": "교열된 문장.", "raw": "자막 원래 문장"}
  ],
  "translations": {                  // 있는 언어만. segments와 1:1
    "ko": [{"idx": 1, "text": "번역 문장"}]
  },
  "corrections": [                   // 교정·교열 기록(검증·감사용)
    {"idx": 12, "from": "출론", "to": "추론", "kind": "term"}
  ],
  "chapters": [
    {"id": "1", "title": "...", "summary": "3~5문장", "segments": [1, 40],
     "start": 3.0, "end": 299.0,
     "children": [{"id": "1.1", "title": "...", "summary": "1~2문장", "segments": [1, 12], "start": 3.0, "end": 88.0, "children": []}]}
  ],
  "mentions": [                      // 영상에서 언급된 자료
    {"kind": "link", "text": "GitHub", "url": "https://github.com", "idx": 30}
  ],                                 // kind: link | book | command | other
  "glossary": [
    {"term": "리포지토리(Repository)", "definition": "...", "analogy": "...", "idx": 25,
     "claim_note": "영상에서는 ~라고 설명"}   // analogy·claim_note는 선택
  ],
  "faq": [
    {"question": "...", "answer": "...", "evidence": [101, 102]}
  ]
}
```

규칙(스키마 + 검사기로 강제):
- `segments.idx`는 1부터 빈틈없이 증가. `start ≤ end`, 시간은 증가 순서.
- `chapters` 1단 개수는 영상 길이로 정한다: 10분 미만 2~4개, 10~60분 4~10개, 60분 이상 6~12개. 각 1단은 하위 0~6개(10분 미만 영상은 하위 없이도 된다). 1단이 문장 1..N을 빈틈·겹침 없이 덮고, 하위가 부모 범위를 정확히 덮는다.
- `translations.<언어>`는 `segments`와 개수·번호가 같다. 원문 언어 키는 넣지 않는다.
- `glossary.idx`, `faq.evidence`, `mentions.idx`는 존재하는 문장 번호.
- 목차·요약·용어집·FAQ·한 줄 소개는 원문 언어와 상관없이 **한국어**.

### 5.2 `index.json` (영상자료실 목록)

`[{id, title, channel, duration, thumbnail_url, field, language, translations: ["ko"], chapter_count, processed_at}]` — 최신이 앞. `lecture.json`에서 자동으로 만든다.

### 5.3 진행 상황 (job)

```json
{"job_id": "<영상ID>-<MMDD-HHMM>", "lecture_id": "<영상ID>", "title": "...",
 "status": "running", "started_at": "...", "updated_at": "...",
 "steps": {"fetch": "done", "correct": "running", "translate": "skipped"},
 "detail": "8/19", "error": null}
```

- 단계(화면 표시 이름): `fetch`(자막 받기) · `preprocess`(정리) · `chunk`(나누기) · `context`(맥락 파악) · `correct`(교정·교열) · `merge`(합치기) · `outline`(목차·요약) · `glossary`(용어집) · `translate`(번역) · `faq`(FAQ) · `assemble`(조립) · `upload`(업로드)
- 단계 상태: `pending` · `running` · `done` · `failed` · `skipped`. 작업 상태: `running` · `done` · `failed`.

### 5.4 서버 API (PC와 Railway가 같은 경로를 쓴다)

| 메서드·경로 | 용도 | PC 미니 서버 | Railway |
|---|---|---|---|
| `GET /`, `/lecture?id=<id>&t=<초>` | 목록·강의 화면 | ✅ | ✅ |
| `GET /api/lectures` | 목록 | 전부 | 공개만(관리자는 전부) |
| `GET /api/lectures/<id>` | `lecture.json` | ✅ | 비공개는 관리자만, 아니면 404 |
| `GET /api/search?q=&field=` | 통합 검색 | ✅ | 공개만(관리자는 전부) |
| `GET /api/health` | 상태 확인 | `{app, home}` | `{app, mode: "hosted", admin}` (폴더 경로는 드러내지 않음) |
| `GET /api/jobs` | 진행 중·최근 작업 | ✅ | 관리자만 |
| `POST /api/jobs/<job_id>` | 진행 보고 | ❌ (플러그인이 파일에 직접 씀) | 업로드 토큰 |
| `PUT /api/lectures/<id>` | `lecture.json` 업로드(교체, 공개 상태 유지) | ❌ | 업로드 토큰 |
| `PATCH /api/lectures/<id>` | `{"public": true}` 공개 전환 | ❌ | 관리자 |
| `DELETE /api/lectures/<id>` | 삭제 | ❌ | 관리자 |
| `POST /api/login`, `/api/logout` | 관리자 로그인 | ❌ | ✅ |

- PC 미니 서버는 **읽기 전용**이다. 쓰기는 플러그인이 파일로 직접 한다.
- 업로드 본문은 `application/json`, 최대 20MB. 서버가 스키마 검사를 다시 하고, 실패하면 400과 이유를 돌려준다.
- 비공개 강의는 목록·검색·단건 조회 **모든 경로**에서 걸러진다(존재 여부도 드러내지 않게 404).

## 6. 처리 흐름

`/video-library <링크> [--translate-en] [--no-upload] [--lang <언어>]` (Codex는 `$video-library`)

| # | 단계 | 담당 | 내용 | 실패 시 |
|---|---|---|---|---|
| 0 | 준비 | 스크립트 | 환경 점검 → 영상자료실 만들기·`app/` 갱신 → 미니 서버 켜기 → 목록 열기 | 설치 명령 안내(승인 후 실행) |
| 1 | 자막 받기 | 스크립트 | 정보·썸네일 주소·자막(json3). 1시간 초과면 예상 시간·사용량 알리고 확인 | 멈춤 |
| 2 | 정리 | 스크립트 | 자막 → 문장 목록 | 멈춤 |
| 3 | 나누기 | 스크립트 | 약 10분 조각(문장 경계 유지) | 멈춤 |
| 4 | 맥락 파악 | AI 1개 | 전체 스크립트 → 맥락표 | 1회 재시도 후 멈춤 |
| 5 | 교정·교열 | AI 조각별 병렬(최대 8) | 맥락표 기반 오전사 교정 + 교열 | 그 조각만 1회 재시도 후 멈춤 |
| 6 | 합치기 | 스크립트 | 검사 → 합치기 | 해당 조각 재실행 |
| 7 | 목차·요약 | AI 1개 | 2단 목차·요약·언급 자료 | 1회 재시도 후 멈춤 |
| 8 | 용어집 | AI 1개 | 용어·정의·비유 | 빼고 계속 |
| 9 | 번역 | AI 조각별 병렬 | 외국어→한국어, `--translate-en`이면 한국어→영어 | 빼고 계속 |
| 10 | FAQ | AI 1개 | 예상 질문 5~10개 + 근거 문장 | 빼고 계속 |
| 11 | 조립 | 스크립트 | `lecture.json`·스크립트 파일 → 원자적 교체 → `index.json` 갱신 | 멈춤(기존 결과 보존) |
| 12 | 업로드 | 스크립트 | 토큰이 있으면 Railway로 전송 | PC 결과 유지, 나중에 재업로드 안내 |

- 진행 상황은 단계마다 `jobs/`에 기록하고, 토큰이 있으면 Railway에도 보고한다(3초 안에 응답이 없으면 넘어감).
- 각 단계는 파일을 남기므로 **실패한 단계부터** 다시 실행한다.
- Codex에서 병렬 에이전트를 쓸 수 없으면 조각을 순서대로 처리한다.

### 6.1 자막 받기 규칙
1. `yt_dlp.YoutubeDL(...).extract_info(url, download=False)`로 정보를 받는다.
2. 원문 언어: 정보의 언어 값 → 자동자막 중 원문 표시 트랙 → 둘 다 없으면 멈추고 `--lang`을 안내한다.
3. 자막 선택: 원문 언어의 **사람이 만든 자막 > 자동자막**. 유튜브가 기계 번역한 다른 언어 자막은 쓰지 않는다.
4. 형식은 json3(단어·시간 정보 포함). 영상 파일은 받지 않는다.

### 6.2 AI 브리프 핵심 규칙 (원문은 `SKILL.md`에 작성)

**맥락 파악 →** `build/context.json`
- 전체 스크립트를 읽고 `{field, one_liner, topic_summary, key_terms: [{term, heard_as: [...], note}], proper_nouns: [...]}`를 만든다.
- `heard_as`는 자동자막이 잘못 받아 적었을 법한 표기(예: `추론` ← `출론`). 분야는 dev/finance/science/medical/other 중 하나.

**교정·교열 →** `build/chunks/NN.edits.json` = `[{idx, text, changes: [{from, to, kind}]}]` (바뀐 문장만)
- 교정(`term`): 맥락표와 앞뒤 문맥으로 볼 때 **명백히 잘못 인식된** 용어·고유명사만.
- 교열: 띄어쓰기·문장부호는 자유롭게 고친다. 맞춤법(`spelling`)은 고친 곳을 `changes`에 적는다.
- **말한 내용은 바꾸지 않는다.** 군더더기 제거·문장 재구성·요약 금지. 확실하지 않으면 두지 않는다.

**목차·요약 →** `build/outline.json`: 5.1의 목차 규칙. 제목은 30자 이내, 화자의 어휘를 쓴다. 요약은 말한 내용에 충실하게(평가·추가 없이). `mentions`도 함께 만든다.

**용어집 →** `build/glossary.json`
- 영상에서 실제로 설명하거나 다룬 용어만(지나가며 언급한 것 제외). 20분 영상 8~25개, 3시간 영상 20~60개, 처음 나온 순서.
- 정의는 1~2문장의 **일반적으로 인정되는 지식**으로, 비전문가가 이해할 수준으로 쓴다. 비유는 핵심 원리를 담은 일상 비유 한 문장(정직한 비유가 없으면 생략).
- 금융·의학 등에서 영상 속 주장은 정의에 섞지 않고 `claim_note`("영상에서는 ~라고 설명")로 구분한다.

**번역 →** `build/chunks/NN.<언어>.json` = `[{idx, text}]`: 문장 하나에 번역 하나. 용어는 맥락표 표기를 따른다.

**FAQ →** `build/faq.json`: 학습자가 물을 법한 질문 5~10개. 답은 **영상에 근거가 있는 내용만** 쓰고 근거 문장 번호를 붙인다. 투자 조언·진단 등 영상 밖 내용은 덧붙이지 않는다.

### 6.3 검사기 (`validate`)
| 대상 | 합격 조건 |
|---|---|
| 공통 | JSON 형식, 존재하는 문장 번호, 담당 범위 안 |
| 교정·교열 | 원문에 `changes`를 적용하고 **띄어쓰기·문장부호를 뺀 글자**가 결과와 같아야 한다. `changes` 한 건은 20자 이내, 문장당 바뀐 글자 비율은 30% 이하 |
| 목차 | 5.1 덮기 규칙, 개수 범위 |
| 번역 | 문장 수·번호 1:1, 빈 번역 없음 |
| 용어집·FAQ·언급 자료 | 필수 필드, 번호 존재 |

불합격하면 오류 내용을 브리프 끝에 붙여 1회 재실행한다.

### 6.4 나중 요청
| 요청 | 동작 |
|---|---|
| `/video-library 번역 <영상ID>` (뷰어 [영어 번역 요청] 버튼이 복사하는 문장) | 9단계(한국어→영어) + 11·12단계만 |

## 7. 화면

공통: HTML·CSS·JS만(빌드 없음), 노트북 기준 + 좁은 화면에서는 위아래로 쌓기. 시간 표시는 `h:mm:ss`.

### 7.1 목록
- 머리: 「영상자료실」, 통합 검색창, 분야 필터(전체·개발·금융·투자·과학기술·의학·보건·기타).
- **진행 카드**(작업이 있을 때 맨 위): 제목, 상태, 경과 시간, 단계 칩(✓ 완료 · ● 진행 · ○ 대기 · 회색 건너뜀 · 빨강 실패). 2초마다 갱신. 완료 **1분 뒤 자동으로 사라지고** [×]로 바로 닫을 수 있다. 완료되면 [보기]. 실패하면 원인 한 줄과 "AI 도구 대화창에서 다시 실행하세요".
- **강의 카드**(최신이 맨 위): 유튜브 썸네일, 제목, 분야 태그, 길이, 챕터 수, 처리 날짜, 번역 표시(`EN→KO`), [보기].
- **통합 검색 결과**: 강의별로 묶어 "일치한 문장 + 시간"(제목·요약·용어집·전사 원문·번역 대상). 누르면 그 장면부터 강의 화면이 열린다.
- 비어 있을 때: "`/video-library <유튜브 링크>`를 입력하세요" 안내.
- Railway 관리자 로그인 시: 카드마다 [공개/비공개], [삭제](확인 후).

### 7.2 강의
- 머리: ← 목록, 제목, 배지(분야·길이·챕터 수), 이 강의 안 검색.
- 플레이어: 실제 유튜브 재생(IFrame API), 챕터 눈금, 현재/전체 시간, 배속 1·1.25·1.5·2, 단축키(J/K/L 10초 뒤·재생/정지·10초 앞, ←/→ 5초, 1~9 대목차). `t` 값이 있으면 그 시간부터.
- 전사: 재생 중 문장 강조·자동 따라가기, 문장 클릭 → 이동. 번역이 있을 때만 [원문|번역|나란히]. [텍스트만 복사]·[시간 포함 복사]는 지금 보는 언어 기준.
- 오른쪽 탭: **목차**(시간·길이, 썸네일 칸 없음) · **노트**(챕터 요약 + 언급 자료) · **용어집**(검색, 정의, 회색 줄 비유, 영상 속 주장 구분, 처음 나온 시간) · **FAQ**(질문, 답, [근거 장면 h:mm:ss]).
- 버튼(복사 후 안내):
  - [영어 번역 요청] — 한국어 강의에 영어 번역이 없을 때만. 복사: `/video-library 번역 <영상ID>`. 안내: "요청 문장을 복사했습니다. video-library 플러그인이 설치된 AI 도구의 대화창에 붙여 넣으세요."
  - [이 강의에 질문하기] — 복사: `video-library 강의 「<제목>」(<영상ID>)에 대해 질문: `. 안내: "질문 문장을 복사했습니다. video-library 플러그인이 설치된 AI 도구의 대화창에 붙여 넣고 질문을 이어 쓰세요."

## 8. 오류 처리와 안전장치

### 8.1 시작 전 점검
| 점검 | 처리 |
|---|---|
| 파이썬 3.10 이상, `yt_dlp` 라이브러리, node 또는 deno | OS별 설치 명령을 보여주고 **승인 후에만** 실행 |
| 링크 | 일반·짧은 링크·Shorts 허용. 재생목록은 "영상 하나씩", 진행 중 라이브는 거부 |
| 영상 상태 | 비공개·연령 제한·회원 전용은 원인 안내 후 멈춤. 계정 쿠키는 요구하지 않음 |
| 자막 없음 | 안내 후 멈춤 |
| 1시간 초과 | 예상 소요 시간·사용량을 알리고 확인 |
| 유튜브 차단(403) | yt-dlp 업데이트 제안(승인 후) |

### 8.2 데이터 보호
- 재처리는 임시 폴더 → 성공 시 교체. 실패하면 기존 결과 그대로.
- 업로드 실패해도 PC 결과는 남고 `업로드` 명령으로 다시 올린다. 재업로드는 교체하되 공개 상태는 유지.

### 8.3 보안
| 대상 | 안전장치 |
|---|---|
| 업로드 토큰 | 저장소·채팅·화면·로그에 넣지 않는다. 사용자가 **자기 터미널**에서 `vl.py connect <서버 주소>`를 실행하면 토큰을 무작위로 만들어 `config.json`에 저장하고, 관리자 비밀번호는 보이지 않게 입력받아, 둘의 **해시만** Railway CLI 표준 입력으로 서비스 변수에 넣는다. AI는 토큰·비밀번호를 묻지도 출력하지도 않고 `connect`를 대신 실행하지 않는다. 기본 서버 주소를 코드에 넣지 않는다(설정한 사람만 업로드) |
| PC 미니 서버 | `127.0.0.1`에만 연결. 포트 8765부터 빈 번호. 1시간 무사용 시 종료. `app/`·`lectures/*/lecture.json`·`index.json`·`jobs/` 밖의 파일 요청 거절(경로 조작 방지) |
| Railway | 관리자 비밀번호는 해시(PBKDF2-SHA256)만 환경변수에 저장. 해시가 없으면 서버가 시작하지 않는다. 세션 쿠키 HttpOnly·Secure·SameSite=Strict, 쓰기 요청은 사용자 지정 헤더 필수. 로그인 시도 횟수 제한. 업로드 토큰도 해시로 비교. 새 강의는 기본 비공개 |
| 진행 보고 | 실패해도 처리는 계속(3초 제한) |
| 테스트 | 운영 Railway 주소로 연결하면 즉시 실패시키는 가드 |

### 8.4 내용 안전
- 용어집 정의는 일반 지식, 영상 속 주장은 `claim_note`로 구분.
- FAQ는 영상 근거가 있는 내용만, 근거 장면 필수. 영상 밖 투자 조언·진단은 쓰지 않는다.
- 공개 저장소에는 남의 영상 내용을 넣지 않는다(테스트 자막은 직접 작성한 샘플만). Railway 공개는 사용 허락을 받은 데모 영상(바이브코딩대학)만.

| 4. Railway 공개 범위 | 로그아웃 상태 | 비공개 강의 주소 직접 접근 404, 공개 데모는 보임 |
| 5. 설치 | 공개 저장소에서 새로 설치 | Claude Code·Codex 각각 처음부터 끝까지, 가능하면 다른 PC/계정에서 안내서만 보고 |

작업마다 `docs/superpowers/evidence/`에 실행 명령·결과(성공·실패·미확인)를 남기고 `docs/handoff.md`를 갱신한다.

## 11. 결정 기록

| 결정 | 이유 |
|---|---|
| 원작 코드를 복사하지 않고 새로 작성 | 원작 저장소에 라이선스가 없어 복사본을 공개 배포할 수 없다 |
| PC 기본 + Railway 선택 | 과제는 Railway 전송·웹 시각화를 요구하고, 다른 사람에게 권할 때는 내 서버에 남의 기록이 쌓이지 않아야 한다 |
| 손님 토큰 없음 | 토큰 발급·관리 부담. 조교·수강생은 PC 모드로 충분하다 |
| Railway는 공개 표시 강의만 공개 | 남의 영상 전사를 통째로 공개하면 저작권 문제가 될 수 있다 |
| 서버·검사 코드를 파이썬 한 벌로 | PC 미니 서버·Railway·플러그인이 같은 규칙을 쓰게 해서 어긋남을 막는다 |
| 영상 하나에 항목 하나 | 자료실 용도에서는 중복 항목이 헷갈린다(원작은 매번 새 항목) |
| 교정 2단계 + 교열(내용 불변) | 강사 안내(전체 맥락 → 교정). 교열은 읽기 쉽게 하되 내용 변경은 검사기로 막는다 |
| 영어 번역은 요청 시, 전사만 | 영어 원문이 필요한 경우는 주로 다른 AI에 넣어 가공할 때다. 토큰 절약 |
| 질문은 플러그인 설치 도구에서, 복사는 질문 문장만 | 전체 스크립트 복사는 너무 길다. 사용자는 Claude Code·Codex 사용자다 |
| 자막 없는 영상 미지원 | 음성 인식은 노트북 부담(수 GB 모델, 장시간 CPU)이 크다 |
| 영상 편집 제외 | 4회차(AWS) 과제로 예상 |
| yt-dlp 파이썬 라이브러리 | 강사 안내 |
| Railway 저장은 PostgreSQL 대신 볼륨 파일(10-06 사용자 결정) | 서비스 1개로 비용이 적고(예상 월 $0.5~1.5), PC용 파일 저장 코드를 그대로 다시 쓴다. 서버 1대만 가능하지만 과제 규모에 충분하고, PC가 원본이라 볼륨이 사라져도 다시 올리면 된다 |
